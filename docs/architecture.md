# SmartFix AI — System Architecture & Design Specification

## 1. Executive Summary
SmartFix AI is an AI-assisted Windows troubleshooting and repair system designed for non-technical users and IT administrators. It automates system diagnostic collection, identifies root causes via a hybrid heuristic rule engine and local LLM reasoning (Ollama), enforces explicit user approval gates, executes allowlisted repair scripts, and verifies resolution post-repair.

---

## 2. Core Architectural Principle
> **"AI Diagnoses; the Controlled Repair Engine Executes."**

To prevent dangerous hallucinations or unrestricted arbitrary shell execution:
1. The LLM produces **STRICT JSON ONLY** conforming to `DiagnosisSchema`.
2. The LLM is restricted to selecting predefined `recommended_repair_id` values from the allowlisted **Repair Registry**.
3. No arbitrary command or PowerShell script generated by the LLM is ever executed.
4. Execution occurs only after explicit user approval.
5. Every repair is followed by an automated verification check.

## 4. Validated Repair Registry

| Repair ID | Name | Category | Risk | Requires Admin | Verification Handler |
|---|---|---|---|---|---|
| `restart_windows_update` | Restart Windows Update Services | Updates | Low | Yes | `verify_windows_update_service` |
| `restart_print_spooler` | Restart Print Spooler Service | Printing | Low | Yes | `verify_print_spooler_service` |
| `restart_audio_service` | Restart Windows Audio Subsystem | Audio | Low | Yes | `verify_audio_service` |
| `restart_bluetooth_service`| Restart Bluetooth Support Service | Bluetooth | Low | Yes | `verify_bluetooth_service` |
| `restart_time_service` | Restart & Resync Windows Time | System | Low | Yes | `verify_time_service` |
| `flush_dns` | Flush DNS Resolver Cache | Network | Low | No | `verify_dns_resolution` |
| `reset_winsock` | Reset Winsock & TCP/IP Stack | Network | Medium| Yes | `verify_network_stack` |
| `renew_ip` | Release and Renew DHCP IP Lease | Network | Low | No | `verify_network_adapter` |
| `restart_explorer` | Restart Windows Explorer Shell | UI | Low | No | `verify_explorer_process` |
| `clear_store_cache` | Reset Microsoft Store Cache | Apps | Low | Yes | `verify_store_cache` |
| `run_sfc_scan` | System File Checker (SFC Scan) | Integrity| Medium| Yes | `verify_sfc_scan` |
| `run_dism_repair` | DISM Health Restore | Integrity| Medium| Yes | `verify_dism_repair` |
| `clean_temp_files` | Clean User & System Temp Cache | Performance| Low | No | `verify_temp_cleaned` |

## 5. College Major Project Viva Demonstration Scenarios

1. **Scenario 1: Stopped Print Spooler**
   - Click "Simulate Stopped Spooler" in Demo Playground.
   - Run Scan in SmartFix AI.
   - SmartFix identifies stopped `Spooler` service (96% Confidence).
   - User approves restart.
   - Spooler is restarted and verified operational.

2. **Scenario 2: Natural Language Troubleshooting**
   - User enters: *"I have no sound and audio is muted."*
   - SmartFix AI diagnoses audio endpoint failure -> recommends `restart_audio_service`.
   - User approves -> Audio subsystem is re-initialized -> Verification confirms running state.

3. **Scenario 3: Offline Heuristic Operation**
   - When Ollama is stopped or unreachable, SmartFix operates entirely offline with its deterministic rule engine without throwing uncaught exceptions.
